# Sprint 2 — Focused Decision Analysis

**Status:** Research/team decision analysis; not an implementation plan  
**Scope:** Sprint 2 only; no preprocessing, tensor generation, or model execution  
**Existing Gate 2 verdict:** Unchanged in [SPRINT_2_PREPROCESSING_AND_DATA_CONTRACT.md](SPRINT_2_PREPROCESSING_AND_DATA_CONTRACT.md)

## Decision frame

The repository describes an eventual unseen-participant classification objective and proposes baselines, but it does not fully freeze the first experiment's inputs, model, or evaluation protocol. This analysis therefore evaluates a conservative candidate scope: use the released trial arrays as supplied, preserve their stored `(385, 56)` representation and `float32` values, attach the Sprint 1 subject/group metadata, make no signal transformation, and evaluate generalization to participants held out by subject. This candidate scope is not team approval and is not a claim that an experiment has been implemented.

Status meanings in this document:

- **MUST RESOLVE:** A minimum contract choice/evidence item blocks a defensible experiment or its interpretation.
- **CAN REMAIN UNRESOLVED:** The uncertainty does not block the candidate raw-input experiment if the stated limitation is respected.
- **TEAM DECISION REQUIRED:** There are viable alternatives; the team must explicitly choose or explicitly defer the item before the stage that depends on it.

## Implications for Sprint 3

The repository separates preprocessing protocol freeze (Sprint 2 / Gate 2) from exact split-strategy freeze (Sprint 4 / Gate 3). The Sprint 3 section of [ML_EXECUTION_PLAN.md](ML_EXECUTION_PLAN.md) says preprocessing implementation can be written before split strategy is available, but execution on all folds depends on that later strategy. Therefore, the unresolved split details do not all need to be settled to define a no-op preprocessing contract; they must be settled before partitioning, model selection, or training.

For a first Sprint 3 implementation scoped strictly to contract validation/raw passthrough, the minimum must be explicitly frozen by the team:

1. Treat the released arrays as the input source without claiming their upstream ICA state is known; no additional ICA or other transform.
2. Preserve the complete `(385, 56)` stored trial and `float32` values; do not crop, re-epoch, resample, reorder, or map channels.
3. Keep subject/group metadata separate from model inputs and use the Sprint 1 composite subject key for any future assignment, subject to reconciliation of the audit's mapping caveat.
4. Exclude filtering, notch filtering, baseline correction, artifact rejection, normalization, and spectral features from this first experiment, unless the team explicitly approves and specifies one before implementation.
5. Do not create processed tensors in Sprint 2; any Sprint 3 data product requires the protocol and output behavior to be approved first.

These are recommendations for a narrowly scoped raw-input baseline, not choices already made by the repository or team.

## Decision summary

### Minimum decisions to freeze before Sprint 3

- The actual first-experiment scope: whether it is a raw-input, no-transform baseline or includes any transformation.
- Whether the released arrays will be used as-is despite unknown upstream ICA state; do not represent them as raw/unprocessed unless evidence is obtained.
- Preserve all 385 positions and 56 columns in stored order, with `float32`; do not assign physical meaning to unresolved axes/channels.
- Confirm the exact subject/group metadata contract and document the Sprint 1 mapping caveat before using the key operationally.
- Specify any preprocessing operation as explicitly excluded or provide evidence, rationale, parameters, and training-only fitting rules before implementing it.

### Uncertainties that can safely remain documented

For a no-transformation raw-input experiment with no physiological interpretation, the physical meaning of position 385, exact 56-channel identities, amplitude units/reference, upstream ICA procedure/state, filtering/notch rationale, baseline interval, artifact labels/rules, and PSD/TBR rationale can remain unknown. This is conditional on preserving values/order, making no unsupported biological or source-processing claims, and not applying those operations. These uncertainties become blockers if an experiment depends on them.

### Decisions requiring explicit team/researcher approval

- Whether to define the first experiment as raw arrays used as released or to seek source-processing provenance/reproduction.
- Whether to include any signal transformation, scaling, artifact handling, or spectral representation; if yes, the scientific rationale and exact method.
- Exact subject-grouped splitter and split assignment, fold count or holdout design, seed, and validation/model-selection protocol before the corresponding experiment stage.
- Balancing/weighting policy and whether primary reporting is subject-aggregated, trial-level on held-out subjects, or both.

### Gate 2 readiness

**Recommended assessment: ready for team sign-off only as a no-transformation raw-input protocol.** The record can be signed off if the team accepts the constrained scope above and explicitly defers the listed transformations; this does not establish their scientific validity for future experiments. If the intended first experiment requires any of those transformations, Gate 2 is not ready until their evidence and parameters are resolved.

This is a readiness recommendation only. The existing Sprint 2 document remains **GATE 2 NOT PASSED** unless and until the required team/researcher approval is recorded through the project's normal review process.
